# 北京中考-哪个学校离我近 · PRD（v0.1 草案）

> 历史版本归档。当前活跃版为 v0.2，见 `docs/PRD.md`。
> 编写日期：2026-05-19

---

## 1. 项目背景与目标

北京中考填志愿时，家长除了关心学校教学水平，**通勤便利度是另一项硬性决策因素**——孩子未来三年每天的上下学时间会被这一次选择决定。现有信息渠道（教委文件、家长论坛、机构推荐）只给学校地址，让家长自己去地图 App 一所一所搜，效率低、横向对比困难。

**本产品唯一目标**：用户输入家庭地址、选择招生区后，**一屏给出该区所有候选高中的通勤数据**（距离、用时、路线），支撑家长横向对比通勤成本。

**不解决**：教学水平评估、分数线匹配、择校全流程咨询。这些是另一个产品的题。

---

## 2. 目标用户与核心使用场景

**目标用户**：北京中考考生家长（约 90%），考生本人为辅。

**用户画像**：
- 在城区或近郊有固定居住地址
- 孩子初三、面对 4-7 月填报志愿窗口
- 已对几所目标学校的"声誉/分数档位"有初步判断，正在做最后排序

**典型使用场景**：
- **场景 A · 志愿填报前夜**：截止前一周，家长在备选 5-10 所学校间做最终排序，把"通勤成本"叠加进决策
- **场景 B · 模拟报考**：成绩出来前，按预估分对应几档学校，想知道每档里哪几所离家最近
- **场景 C · 参观学校规划**：周末计划带孩子去看学校，批量了解某片区域的学校位置分布

## 3. 功能需求

### P0（MVP 必做）

| 编号 | 功能 | 验收标准 |
|---|---|---|
| F-01 | 家庭地址输入 | 输入框支持高德 placeSearch 自动联想；输入≥2 字符后 0.5 秒内出候选；同时提供"在地图上选位置"按钮 |
| F-02 | 选择招生区 | 下拉框可选海淀/西城/朝阳/东城 4 个区；下方一行小字"按你实际能报志愿的区选择（京籍可填户籍区或学籍区，非京籍按学籍区）" |
| F-03 | 选择通勤方式 | 三选一 tab：驾车 / 公共交通 / 骑行；默认驾车 |
| F-04 | 学校列表展示 | 该区所有学校卡片按距离从近到远排序；每卡片显示：校名（分校带"分校"tag）、直线距离、估算通勤用时、学校类型、招生范围；分校平铺为独立条目 |
| F-05 | 前 10 所精确通勤 | 列表前 10 所自动调用高德路径规划，给出精确用时；11 名以后默认显示"点击查看精确时间"按钮 |
| F-06 | 切换通勤方式 | 切换 tab 后 ≤ 3 秒内列表前 10 所通勤时间更新；仅对当前可见学校重查 |
| F-07 | 查看具体路线 | 点击任意学校的"看路线"按钮，弹出地图组件，绘制从家到该校的路径并标注关键节点 |
| F-08 | 记忆上次输入 | 用 localStorage 保存家庭地址、招生区、通勤方式；下次打开自动回填；页面内提供"清除记忆"按钮，点击后立即生效 |
| F-09 | 非北京地址拦截 | 若高德 geocoder 返回的 adcode 不以 11 开头，toast 提示"本工具仅支持北京市内地址，请重新输入"，查询按钮置灰 |
| F-10 | API 限额降级 | 全日额度耗尽时显示顶部 banner"今日访问已达上限，明日 0 点后恢复"；列表仍按直线距离展示，不让用户彻底无功能可用 |
| F-11 | 反馈错误入口 | 页面底部 + 每所学校卡片角落提供"数据有误？反馈一下"链接，跳 `mailto:` 或 GitHub Issues |

## 4. 非功能需求

**性能**
- 首屏可交互（输入框可输入）≤ 2 秒（4G 网络）
- 学校列表（直线距离版）首次渲染 ≤ 3 秒
- 前 10 所精确通勤回填 ≤ 6 秒
- 单条路线渲染到地图 ≤ 2 秒

**兼容性**
- 移动端：iOS Safari 14+ / Android Chrome 90+
- PC 端：Chrome 100+ / Edge 100+ / Safari 14+
- 设计稿以 375px 移动端为准，PC 端响应式自适应放大

**隐私**
- 家庭地址仅活在浏览器内存与 localStorage，**不上传任何自建后端**
- 经纬度发送给高德 API 仅用于地址解析与路径规划，不附带任何个人身份信息

**安全**
- 高德 Key 配置域名白名单
- 高德服务端设置每日调用量上限（初期建议 20000 次/日）

**可维护性**
- 学校数据按区分割 JSON 文件（`schools-haidian.json` 等），追加新区不动核心代码
- 每条学校记录带 `lastVerified` 字段，留存上次校对时间
- 无构建工具，浏览器直接打开 `index.html` 即可运行

## 5. 数据模型

### 学校 School 字段定义

```json
{
  "id": "renda-fuzhong-chaoyang",
  "name": "中国人民大学附属中学朝阳学校",
  "shortName": "人大附朝阳",
  "isBranch": true,
  "parentSchool": "renda-fuzhong",
  "district": "chaoyang",
  "address": "北京市朝阳区太阳宫北街2号",
  "lng": 116.456,
  "lat": 39.978,
  "type": "public",
  "hasInternationalDept": false,
  "admissionScope": "district",
  "lastVerified": "2026-04"
}
```

**关键字段**：
- `type`：`public`（公办普高）/ `private`（民办普高）/ `international-dept`（公办校国际部）
- `admissionScope`：`district`（区内招生）/ `citywide`（全市统招）
- `isBranch + parentSchool`：分校独立条目，通过 parentSchool 关联本部，供未来分组展示使用

### 分校处理方案

- **存储**：每个校区一条独立 JSON 记录，互不嵌套
- **展示**：列表平铺为独立条目，卡片用"分校"小 tag 区分
- **筛选**：分校的招生范围按其实际归属判断（如人大附朝阳归朝阳区），不继承本部

### 数据来源与更新策略

- **首版**：由 AI 助手整理样本数据，用户校对后入库
- **常规更新**：每年中考报名前（3-5 月）人工 review 全部记录一轮
- **持续反馈**：页面"反馈错误"入口收集异常上报

### 高德接口对应关系（重要）

| 产品功能 | 高德接口 | 关键返回字段 |
|---|---|---|
| 地址联想 | placeSearch (Web JS API) | tip.location |
| 地址校验 | geocoder | adcode（用于北京归属判断） |
| 驾车路径 | driving | distance, duration |
| **公共交通**路径 | **Transfer**（综合换乘，含公交/地铁/市郊铁路） | distance, **duration**（用作排序）, segments |
| 骑行路径 | riding | distance, duration |

**注**："公共交通"在 UI 上是单一选项，后台对应高德 **Transfer** 接口的综合换乘结果，**不**单独区分纯公交或纯地铁。默认按 `duration` 升序排序，不按费用或换乘次数。

## 6. 关键交互流程

### 流程 1 · 首次访问到看到列表

1. 用户打开 H5 → 首页：[家庭地址输入框] + [招生区下拉] + [通勤方式 tab]
2. 输入"望京西园" → placeSearch 联想出现候选 → 用户点选
3. 选择招生区"朝阳" → 通勤方式默认"驾车"
4. 点"查询" →
   - 检测 adcode 是否 11 开头：非北京则拦截
   - 调 geocoder 拿家的经纬度
   - 加载 `schools-chaoyang.json` → 本地 Haversine 算每所学校直线距离 → 升序展示全部
   - 同时对前 10 所并发调 driving 接口 → 精确用时回填卡片
5. localStorage 写入这次输入

### 流程 2 · 切换通勤方式

1. 用户从"驾车"切到"公共交通"
2. 列表不动，前 10 所卡片上"用时"字段进入加载状态
3. 并发调 Transfer 接口（出发时间默认下周一 07:30）
4. ≤ 3 秒回填新结果，按 duration 重排前 10 所

### 流程 3 · 查看具体路线

1. 用户在某所学校卡片点"看路线"
2. 弹出全屏地图组件，绘制路径
3. 标注关键节点（公交：站点名；驾车：主要路口；骑行：转弯点）
4. 关闭返回列表，列表状态保留

## 7. 异常与降级方案

| 异常情况 | 处理方式 |
|---|---|
| 家庭地址识别失败 | toast"地址识别失败，请换个更具体的地点（如门牌号、小区名）"，按钮置灰 |
| 家庭地址在北京外 | toast"本工具仅支持北京市内地址" |
| 单所学校路径规划失败 | 该卡片用时字段显示"-"，不阻塞其他学校查询 |
| 高德 API 全日额度耗尽 | 顶部 banner"今日访问已达上限，明日 0 点后恢复"；列表仍可见，仅展示直线距离与排序 |
| 网络断开 | toast"网络异常，请检查网络后重试"，保留已加载结果 |
| localStorage 不可用（隐私模式） | 静默降级，不报错；当次会话功能正常，下次需重新输入 |

## 8. 边界与非目标

本期**坚决不做**（避免 scope creep）：
- 学校教学水平评分、师资介绍、办学特色
- 历年分数线、录取人数
- 用户注册登录、跨设备数据同步、社交分享
- 中职、职高、技校、纯国际学校
- 北京以外城市
- App / 小程序原生版本
- 学校多端对比已下放 P1，MVP 不做

## 9. 未决事项 / TODO

- **样本数据准确性的最终责任**：MVP 数据 AI 整理初稿、用户校对——若校对不充分，错数据上线归谁？建议页脚标注"数据由 AI 辅助整理，最终请以学校官方公告为准"作为兜底
- **localStorage 跨浏览器一致性**：同一用户在手机 Safari 与电脑 Chrome 数据不互通——是否需要 UI 提示？建议 MVP 不提示，靠用户自然理解
- **公共交通出发时间是否区分早晚**：上学 07:30 出发到校 vs 放学 17:00 从校回家——是否双向都算？建议 MVP 只算上学单程
- **学校卡片视觉层级具体排版**：留给开发阶段按设计稿迭代
- **高德 Web 服务接口的白名单形式**：JS API 走域名白名单，REST 调用需 IP 白名单——纯前端是否会触发后者？开发阶段验证
- **反馈入口形态选 mailto 还是 GitHub Issues**：开发阶段一句话决定，影响极小
